# 使用手册

本手册使用 Agent Motion 1.6.0。DeepSeek Harness 制作页接受人物 MP4、配音与字幕文案，默认从视频复刻音色，也支持已有音色 ID。经 CosyVoice-v3.5-plus 配音、MuseTalk 数字人口播后，进入 Agent Motion 的抠像、排版和 Three.js 制作管线。支持科技感、教育风、营销风，交付 H.264 MP4、可编辑 Three.js 工程 ZIP 与 HTML 预览。安装与服务配置见 [部署说明](deployment.md)。

## 页面快速开始

1. 先在 Harness 首页完成现有登录，点击左侧“动效工坊”，制作页会显示在右侧内容区。也可直接打开同地址的 `/agent-motion/`。页面复用 Harness 的 token/cookie 认证，无需另配账号或在制作页保存令牌。
2. 确认页面“制作服务已配置”。未配置时打开 Harness“设置 → 动效工坊”，填写 DashScope、MuseTalk 和腾讯云 COS 配置并保存，制作页会自动更新配置状态；仍可点“重新检查配置”手动核对，无需编辑环境文件或重启。密钥留空保留已有值，明确勾选“清除”才删除，保存后输入框清空。读取和保存设置不创建收费任务。选择或拖入不超过 1 GB 的人物 MP4，填写希望数字人说出的简体中文文案，也可导入 UTF-8 `.srt`、`.txt`。文案同时用于配音与字幕；SRT 只取正文配音，原时间轴会按新配音重新对齐。
3. 默认选择“使用视频音色”，无需填写音色 ID。上传视频须有清晰单人说话音轨；自动提取开头最多 20 秒，须有至少 5 秒清晰说话。片头静音时，先截取合适说话片段再上传；无声视频无法复刻音色。也可选“使用已有音色 ID”，此时须填写绑定 CosyVoice-v3.5-plus 的有效 ID；管理员配置的默认 ID 只预填此栏，不改变默认视频选项，系统音色名称不能替代该 ID。可填写中文标题，选择科技感、教育风或营销风，以及 1920×1080、1080×1920、1080×1080 或 1280×720 画幅。
4. 点击“开始制作”后，视频模式会用原视频声音云端复刻音色，再执行收费配音和数字人生成；已有 ID 模式直接生成配音。随后创建 Harness 制作会话，实际加载 `agent-motion` Skill，按本地 SRT 分析与 Motion Craft 规则抠像、排版、合成及渲染。页面显示八个阶段：上传原片 → 复刻音色 → 生成配音 → 数字人口播 → 字幕对齐 → 人像抠图 → 场景合成 → 渲染输出；已有 ID 模式的复刻阶段显示“已跳过”。进度优先使用后端记录的实际阶段，旧任务才按阶段说明识别。“查看配音与数字人素材”可试听和查看已有中间产物。刷新或从侧栏返回会恢复当前任务的文案、音色来源、标题、风格、画幅和状态。视频模式即使已创建音色 ID，也保持“使用视频音色”。
5. Harness 要求工具操作审批时，制作页显示原因和完整参数。检查后选择“允许本次操作”，或“拒绝并停止”；每次决定仅针对当前操作。Windows 下 Node 派生 Python、FFmpeg 或 Chromium 时，宿主可能限制子进程管道并返回 `EPERM`，不能据此认定依赖未安装；须检查并确认本次完整命令和工程路径，通过 Harness 对该操作的精确审批继续。页面沿用宿主审批，不改变全局权限。
6. 完成后在结果区播放或下载 MP4、下载可编辑 Three.js 工程 ZIP，或打开 HTML 预览。预览与成片使用同一任务的工程；下载 ZIP 包含预览依赖与素材，不能只保存一个 `index.html` 后直接双击预览。页面的会话链接进入 Harness 首页，在“Agent Motion 制作”工作区按显示的“视频制作 · 风格 · 任务编号”查找当前任务。需要改稿时在该会话继续编辑工程，或编辑解压后的工程，再按下文重渲染和验收。

视频复刻成功后，页面显示“本次音色 ID”，后续制作可选择“使用已有音色 ID”并填写此 ID，复用已创建音色。

腾讯云 COS 设置使用私有存储桶，Bucket 填写完整 `name-APPID` 名称；默认 Endpoint 为 `https://cos.ap-beijing.myqcloud.com`，区域从地址识别。填写 COS SecretId、SecretKey，使用 STS 时再填写 SessionToken；凭据只需所需素材对象的 `PutObject` / `GetObject` 权限。素材通过三小时有效且公网可访问的 COS 签名链接交给阿里音色复刻及数字人服务，存储桶保持私有。配音仍由阿里百炼北京区域 CosyVoice 提供。

页面用新配音驱动人物口型，成片使用生成配音，不以人物原片的口播内容作为字幕。制作会话先通过 `scripts/prepare-avatar.mjs` 将云端数字人视频和配音合为 `voiced-avatar.mp4`，强制使用新配音并保留完整尾音；数字人视频无法覆盖完整配音时停止报错，再按 `narration.txt` 对齐字幕并进入原 Skill。折叠的数字人预览显示上游原视频，最终音轨以生成配音为准。CPU faster-whisper 首次使用需要下载模型。原片和配音上传腾讯云 COS 私有存储，以三小时有效的签名链接供生成服务读取；浏览器只播放宿主同地址提供的本地产物。

视频音色模式缺少 FFmpeg 或 FFprobe 时，会自动在插件安装目录外的制作工程运行 `node scripts/bootstrap.mjs`，并检查两项媒体工具后才调用付费 API。首次准备需要联网，可能耗时较长；部署建议预先运行 bootstrap，详细工程路径与命令见 [部署说明](deployment.md#准备独立制作工程)。已有音色 ID 模式直接生成配音，后续环境沿用原 Skill 的安装步骤。

每次执行会按上游服务计费，视频模式还会调用音色复刻。停止本地任务不保证撤销已经创建的复刻、配音或数字人收费任务。执行接口明确返回未受理的 `409`（已有任务或状态不允许）或 `503`（配置或服务尚未就绪）时，排除原因后可重试当前任务；页面不会因此一直锁定提交按钮。连接中断、提交超时或 `500` 等无法确认是否受理的结果仍显示“提交状态待核对”，即使刷新也不会重复收费提交；通过“重试”查询状态，必要时请管理员核对上游任务记录，不新建相同收费请求。API 凭据只在“设置 → 动效工坊”填写并存于服务器，不回显、不保存在浏览器存储；勿填入文案、音色栏或聊天。

若页面提示 401 或登录已失效，回到同一 Harness 首页登录，再返回制作页查询状态。以下为原声素材的自然语言与工程 CLI 工作流，仍可直接使用；页面已生成的数字人素材也由同一制作管线处理。

## 修改制作 Skill

工坊新任务使用最新 Skill 的制作要求、排版、字体和效果。修改 Harness Skills 列表显示的实际文件及其引用资料；两个主要制作规则位于实际 Harness home 下：

```text
agent-motion/production/.agents/skills/motion-craft/SKILL.md
agent-motion/production/.agents/skills/srt-reference-to-three/SKILL.md
```

也可修改同一工程的 `AGENTS.md` 调整规则入口。`agent-motion` 入口默认来自插件安装目录；需要持久自定义入口时，将完整入口目录复制到 `agent-motion/production/.agents/skills/agent-motion/` 后再编辑，此工程版本优先于安装包。优先修改制作工程中的规则，避免替换插件包时丢失自定义内容。

保存后无需重启，新任务点击“开始制作”即读取新规则。首次执行时，规则和引用文件会复制到 `inputs/studio/<任务编号>/rules/`，`revision.json` 记录本次版本；执行中的任务、重试同一任务及已完成视频保持当时规则。模板只生成可编辑初版，制作会话随后按任务规则调整 `scene.mjs`、`film.json` 再渲染。修改 Skill 不会自动重制旧视频，也不改变上传表单、配音或数字人的 API 配置。

## 1. 原声素材工作流：提供素材与制作要求

在 DSH Web 打开一个可读写的工作区，提供原视频和完整、对齐时间的 UTF-8 SRT。说明片名、目标观众、风格和画幅，例如：

> 使用 agent-motion，在当前工作区新建 my-film。原片和完整 SRT 已提供。风格：教育风；标题：三个步骤学会整理信息；受众：刚接触 AI 的学生；画幅：1920×1080，30 fps。先保存 brief 和素材，检查字幕时间，准备并检查同步人物层，再生成 Three.js 初版。按本地 SRT 分析与 Motion Craft 规则改进，保留原声音、口播顺序和时间，交付 MP4、可编辑工程与检查记录。

| 风格 | 用途与起点 |
| --- | --- |
| 科技感 | 技术、AI 和产品讲解；科技色彩与空间动效。 |
| 教育风 | 知识、课程和步骤讲解；突出信息结构与阅读节奏。 |
| 营销风 | 产品卖点和活动讲解；突出标题、重点与行动信息。 |

三种模板提供字体、配色、人物和字幕布局。指定参考、改稿要求和实际内容仍决定最终设计；智能体应继续编辑工程，不能把模板渲染视为艺术验收。brief 中建议明确写一项 `风格：`，避免同一句同时要求互斥风格。

原声素材 CLI 使用 OpenCC 1.4.2 转为简体并保留 SRT 时间轴。纯英文字幕须先让 Harness 模型翻译成中文并核对时序；纯文本对齐只适用于对应录音的字幕。CLI 不自行调用配音与数字人服务，页面则使用上述收费生成流程。

## 2. 初始化并安装工程

入口 Skill 会在插件安装目录外创建独立制作工程。已有 Agent Motion 工程直接续作；新目录须不存在、父目录须存在。随后智能体从制作工程根执行：

```sh
node scripts/bootstrap.mjs
node scripts/doctor.mjs --matting --json
```

首次运行需要联网下载 Python 环境、浏览器、媒体工具和人物抠像模型。安装通过后，保存或复制输入：

```text
inputs/
  source.mp4
  source.srt
  brief.txt
```

`brief.txt` 例如：

```text
风格：教育风
标题：三个步骤学会整理信息
要点：理解概念／观察示例／动手练习
受众：刚接触 AI 的学生
要求：保留原始口播、声音与字幕时间，重点突出三个步骤。
```

标题须含中文且不超过 36 字。可选 `要点：` 须提供三个中文要点，以 `／` 分隔，每个不超过 18 字；要点应对应实际口播。省略时，初版从 SRT 开头、中段和末尾取字幕摘录，不使用模板示例编造内容，智能体仍需检查摘录是否概括准确。

命令和阶段规则均从工程副本执行。先完整读取 `AGENTS.md`、`.agents/skills/srt-reference-to-three/SKILL.md`、`.agents/skills/motion-craft/SKILL.md`，按其阶段要求读取引用，完成 SRT 分析和制作交接。

## 3. 检查人物层并生成初版

先处理两秒样片，检查人物边缘和同步，再处理完整影片：

```sh
node scripts/matte.mjs --input inputs/source.mp4 --output work/person-preview --seconds 2
```

从工程根运行实际生产 CLI：

```sh
node deepseek/lib/produce.js --video inputs/source.mp4 --srt inputs/source.srt --brief inputs/brief.txt --output work/my-film --style 教育风 --width 1920 --height 1080 --fps 30
```

`--style` 支持科技感、教育风、营销风；省略时根据 brief 选择，无明确匹配时使用科技感。`--width`、`--height` 默认 1920×1080，须为 128–4096 的偶数；`--fps` 默认 30，须为 1–60 的整数。SRT 不得为空、乱序或重叠，末条不得超出原视频时间。

原始背景默认替换。需要保留时加 `--keep-background`；仍会生成同步人物层，原背景保留时不描人物边缘。换背景时按 Skill 的人物描边与空间规则检查合成。

换背景时，默认用透明度遮罩的上半身质心校准水平取景，并从顶部保留头部。此方法不是人脸识别；多人物或明显偏心的镜头须检查并用 `--person-x 0.5 --person-y 0.35 --person-scale 1` 等参数修正。横纵锚点范围为 0–1，缩放范围为 1–3；锚点描述原片内的取景位置。

需要背景音乐时，将有权使用的文件放到 `inputs/`，在生产命令后添加 `--music inputs/music.wav --music-volume 0.08`。音量范围为 0–0.3，默认 0.08；BGM 与原声混合，试听确认不会遮盖口播。原片没有音轨时只输出 BGM，不会生成语音。

需要 AI 生图背景时，按 [豆包生图说明](image-generation.md) 配置本地 Key，生成并检查图片，再添加 `--background-image inputs/generated/hero/image-1.png`。也可直接使用自备 PNG/JPEG/WebP；图片会复制进影片并按画幅居中裁切，模板底色遮罩保持中文可读。重渲染复用本地图片，不再次生图。

先创建工程但暂不导出 MP4 时加 `--preview-only`。此选项仍处理 CPU 人物层，并保存 Three.js 工程；随后编辑、预览，再运行该工程的 `render.mjs` 导出。

输出目标必须是制作工程 `work/` 内的新目录。已有目录会被拒绝，已有 `final.mp4` 也不会覆盖；下一轮使用新的任务目录，或先妥善重命名旧成片。复制或渲染失败时保留素材与部分产物供诊断。

## 4. 预览、修改与重渲染

在工程根启动本地预览：

```sh
node serve.mjs
```

打开 `http://127.0.0.1:8793/work/my-film/`。智能体按两个本地 Skill 修改 `work/my-film/scene.mjs` 与 `film.json`，逐段检查构图、中文可读性、空间层次、人物取景和连续动作。随后从工程根运行：

```sh
node work/my-film/render.mjs
```

已有 `final.mp4` 须先重命名保存。渲染按绝对时间逐帧采集，FFmpeg 导出 H.264 视频并混入原录音的 AAC 音轨及可选 BGM。无音轨的原片不会产生口播声音，需先确认输入正确。编码成功会移除本次中间文件 `final.pending.mp4`；失败时该文件保留供诊断，修复后先重命名保存，再重试渲染。

| 产物 | 用途 |
| --- | --- |
| `final.mp4` | 最终编码视频；生成后仍需实际视听检查。 |
| `scene.mjs`、`film.json` | 可编辑场景与影片配置。 |
| `index.html`、`render.mjs` | 预览与重新导出入口。 |
| `validation.json` | 编码、时长、帧数、音轨及待验状态记录。 |
| `person/` | 同步前景、透明度遮罩与抠像记录。 |
| `source.mp4`、`source.srt`、`brief.txt` | 本轮输入副本与制作要求。 |

## 页面工程 ZIP

结果区的工程下载会把当前任务及其所需素材、字体、Three.js 和重渲染脚本打包为 ZIP，首次下载时生成。以前已完成的任务也可下载，无需重新调用配音或数字人。新任务的规则快照同时保留在包中；旧任务没有快照时不会补写当时的规则。包不包含服务密钥、其他任务、逐帧 PNG 或平台运行环境。

完整解压后，在解压根目录运行：

```sh
node serve.mjs
```

打开 `http://127.0.0.1:8793/work/<任务编号>/` 即可预览 HTML。保留解压目录结构，编辑该任务的 `scene.mjs`、`film.json` 后刷新预览；无需 Harness 登录或云 API。直接通过 `file://` 打开 HTML 会受到浏览器模块及资源读取限制。

重渲染需要本机 FFmpeg、FFprobe 和 Chromium。FFmpeg/FFprobe 默认从 PATH 查找，也可设置 `FFMPEG_PATH`、`FFPROBE_PATH`；浏览器默认使用 Playwright 缓存，可设置 `BROWSER_EXECUTABLE` 指定浏览器，或 `BROWSER_CHANNEL=msedge` / `chrome` 使用已安装浏览器。也可在解压根目录下载 Chromium：

```sh
node node_modules/playwright-core/cli.js install chromium
```

先保存并重命名包内已有的 `work/<任务编号>/final.mp4`，再运行：

```sh
node work/<任务编号>/render.mjs
```

该操作复用包内人物层与音频，只重新导出本地视频，不重新复刻、配音或调用数字人。ZIP 未附带 FFmpeg、Chromium、Python 或抠像模型；重新抠像须使用前述完整制作工程的安装流程。

## 验收与归档

先提取代表帧并制作低分辨率拼图，或用缩略图、局部裁切检查；小字、脸部和边缘无法判断时再看对应原图。然后连续播放完整 MP4、试听原声，核对人物边缘、字幕同步、完整时长、动作衔接和黑帧。原视频背景保留时禁止描人物轮廓；换背景时检查规则要求的宽阔风格化描边。具体标准以工程原始 Skills 为准。

`validation.json` 的渲染成功和编码检查不代表视听验收通过。宿主不能看图、连续观看或试听时，智能体须记录具体缺口并交付待检查预览，补人工或具备相关工具的检查后再接受成片。

页面任务可用结果区的工程 ZIP 归档与迁移；按上一节准备目标机器的浏览器及媒体工具。原声素材 CLI 工程仍需保留完整工程根，包括依赖、字体、模板、原片、SRT、人物层和 `work/my-film/`；单独复制影片子目录不足以重新渲染。跨平台迁移完整工程时保留锁文件，在目标平台重建浏览器、Python 和媒体运行环境；原输入与工程不能为修复安装问题而删除。

## 常见问题

| 现象 | 操作 |
| --- | --- |
| 制作页提示 401 或登录失效 | 回到同一 Harness 首页登录，再返回 `/agent-motion/` 重试。 |
| 制作服务尚未就绪 | 打开 Harness“设置 → 动效工坊”补全配置并保存，制作页自动更新；可点“重新检查配置”手动核对，无需重启。 |
| 音色 ID 无效或不属于指定模型 | 使用绑定 CosyVoice-v3.5-plus 的有效音色 ID，勿用系统音色名称。 |
| 提交状态待核对或上游请求超时 | 查询已有任务并让管理员核对上游记录，避免重复收费提交。 |
| 纯文本对齐提示口播不匹配 | 将文本改为原片实际口播，或提供已核对时间轴的 SRT，再新建任务。 |
| npm 运行时业务参数不生效 | Windows PowerShell 改用本文的 `node ...` 命令，避免包装器吞 `--`。 |
| 下载失败或校验失败 | 保留完整报错，恢复官网下载源的访问，再执行同一安装命令；不要绕过哈希校验。 |
| Linux 浏览器缺少系统库 | 在工程根运行 `node scripts/setup.mjs --with-deps`，必要的系统安装可能需要管理员权限。 |
| 字幕提示英文、重叠或超时 | 先修复或翻译 SRT，保留原正确时间轴，再用新任务目录制作。 |
| 人物边缘不合格 | 先检查两秒样片，核对抠像、时序和原片质量；按本地人物规则修复后再全片渲染。 |
| 多人物或主体偏心、头部取景不合适 | 在新一轮生产中明确 `--person-x`、`--person-y`、`--person-scale`，或修改 `film.json` 的 `framing` 后重渲染并检查。 |
| 无法选择风格或 brief 提到多种风格 | 写清 `风格：科技感`、`教育风` 或 `营销风`，或传一个明确 `--style`。 |
| 成片已存在 | 保存并重命名旧成片后重渲染，或创建新任务目录，避免覆盖。 |
| 编码失败后重试提示中间文件已存在 | 保留报错，将 `final.pending.mp4` 重命名后重试；勿覆盖旧成片。 |
